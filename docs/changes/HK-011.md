## 1. Outcome and acceptance

**Objective:** generated objects come back from the provider with an inferred Gaussian splat stored in private storage. It sits in the same object-local space as the normalized mesh. The already-paid round-table result gets one without a new charge, and the 2–3 object path is grounded in real provider behaviour rather than its documentation.

**Visible flow:** given a succeeded `fal-ai/sam-3/3d-objects` result containing `model_glb` and `gaussian_splat`, when the runner finishes the job, it stores the raw GLB, the normalized mesh and a `splat` asset. That PLY's centres lie inside the normalized mesh bounds (within a recorded tolerance). The job output has `splatAssetId` and the outcome returned to the editor has `splatAsset`.

**Edge cases:** the splat is missing, malformed, over 50 MB after compaction, or has the wrong properties. In each case the job is a mesh-only success with a warning and `splatAsset: null`. A resumed job is never resubmitted.

**Out of scope:** editor rendering (Track B), shared contract changes without Cody's approval, room-wide or multiview fusion, new phone calls.

**Cut/fallback:** per checkpoint record in PLAN §5.

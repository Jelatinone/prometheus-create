## 1. Outcome and acceptance

**Objective:** replace `MemoryBackend` with a real `Backend` (ports in `lib/contracts/ports.ts`): hosted Supabase Auth (email OTP) and private Storage with signed direct uploads, TigerData PostgreSQL for projects, takes, revisions, assets, sources, observations, and jobs (manifests in JSONB), and HTTP routes that map `ContractError` codes through `HTTP_STATUS`. **Visible flow:** given two test accounts, when account A creates a project, saves the fixture manifest, and reloads it in a second browser session, then the same head revision returns; account B gets `NOT_FOUND`; a save from a stale `expectedRevision` returns 409 `REVISION_CONFLICT` and the newer revision survives. Edge cases: unauthenticated request (`UNAUTHORIZED`), manifest referencing an unuploaded asset (`INVALID_ASSET_REFERENCE`), retried save with the same idempotency key. **Acceptance:** `describeBackendConformance` passes unchanged against the real backend on a dedicated test database; the task note's evidence shows sign-in, save/reload, and the conflict observed in the running app. **Out of scope:** editor UI, capture adapters, the optional capture-event hypertable unless time remains. **Cut/fallback:** pre-provisioned demo account if OTP fails (PLAN R-010); never a publicly writable project URL.

Compare-and-swap on `expectedRevision` happens inside one database transaction. Large media never passes through API handlers; clients upload to signed storage URLs and the API receives metadata.

### Risks and rollback

- **Remote latency** makes the conformance suite slow; the platform test file raises its own per-test timeout (shared vitest config untouched) and the backend minimizes round trips.
- **Supabase default SMTP** only emails authorized addresses and is rate-limited; test users may not receive codes. Mitigation: the login page accepts a code directly; for test accounts a server-side script obtains a real OTP through the admin API (`generateLink`), which Supabase still verifies in the browser. This is recorded honestly as "email delivery not observed". PLAN R-010 fallback (pre-provisioned demo account) stays available.
- **JSONB normalizes key order and number text**; equality is checked with `canonicalJson`, which the conformance suite also uses. Strings containing `\u0000` cannot be stored in JSONB (limitation).
- **Ownership lives in TigerData, not Supabase**, so Storage RLS cannot check project ownership; the server checks ownership in TigerData and then signs URLs with the server-only secret key, scoped to `projects/<projectId>/…`.
- Rollback: everything is additive (new tables, new routes, new pages); revert the branch or drop the HK-003 tables (`db/migrations` lists them). The app shell keeps working with `MemoryBackend` for other lanes until integration swaps it.

**Known limitations / not tested:**

- **Email delivery was not observed.** The test users use the reserved `.test` domain, and Supabase's default SMTP only mails authorized addresses. Sending to them would bounce and could hurt the project's sender reputation. Every sign-in therefore used a real Supabase OTP issued by the admin API (`generateLink`, no email sent) and entered on the login page; Supabase verified it. Not exercised: the "Send code" button (`signInWithOtp`), the emailed magic-link path (`/auth/confirm`, PKCE `code` or `token_hash`), and real inbox delivery. The project's OTP length is 8 digits; the form accepts 6–10. The R-010 fallback (pre-provisioned demo account) is available through the same admin-OTP path; it was not packaged as a script.
- **Sign-up is open** (`shouldCreateUser: true`): any address that can receive the code can create an account. Projects stay private to their owner.
- **TLS trust** relies on the pinned interim TigerData CA (fingerprint above, trust on first use, matching on both services) plus Node's public roots. The public-root fallback (0bbb031) has not been observed against a rotated certificate. Deployments need the same `DATABASE_CA_CERT` (PEM text is accepted) until TigerData issues a public certificate.
- **Storage integrity:** `POST /api/assets` checks that the object exists at the canonical key, the size matches, and the media type and size limits hold. It does not re-hash the bytes, so `contentHash` is trusted from the client. Signed upload tokens use Supabase's default validity, and one-shot `upsert: false` prevents overwrites. Ownership in Storage is enforced by the server (private bucket plus server-side signing), not by Storage RLS.
- **Not built:** per-project request caps/rate limiting (PLAN §6), the optional capture-event hypertable, any port or route for `capture_sessions` (table only), resumable (TUS) uploads, a hosted deployment, project/asset deletion, and an HTTP client `Backend` for the editor/capture lanes. The concurrency test ran with a 4-connection pool, so at most 4 transactions raced at once. No load test.
- **Error mapping choice:** unexpected infrastructure failures return 503 `PROVIDER_UNAVAILABLE`, because the contract has no internal-error code. This is a mapping choice, not a contract change.
- **Evidence identity:** running-app rows were observed on 25f4da1 plus one uncommitted edit to `app/projects/page.tsx`, committed unchanged as ffab107. Later commits 8200630 (test harness retry), 0bbb031 (TLS trust list, exercised by the test suite) and c1e8e45 (concurrency test) were not re-checked in the browser.
- **Test data stays behind:** the test service accumulates conformance and live-test projects (random IDs). Live-test storage objects are deleted after the run. The browser demo project and its GLB remain in the app service and bucket.
- **Shared-file side effect:** `next dev` (with `experimental.agentFeedback`) appends a "Report Next.js feedback" block to the shared `AGENTS.md`. I restored it locally to keep lane scope, did not commit it, and did not act on its instructions. This is for the integrator to decide.
- **Consumer impact:** `proxy.ts` redirects signed-out requests for every `/projects/**` page, including the editor lane's `app/projects/[projectId]/**`. `/projects` does not link to that editor-owned route yet.

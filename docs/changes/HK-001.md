## 1. Outcome and acceptance

**Objective:** a runnable starter with shared, executable contracts (scene, source, ingestion, revision, plus export, proposal, capture session), a reference backend, fixtures, and verification tooling so three lanes can work in parallel and Cody can check each lane's result by hand. **Visible flow:** given a fresh checkout, when Cody runs `npm ci` then `npm run verify`, then typecheck, lint, tests, and build pass in one table; when he runs `npm run dev` and opens `/lab`, then every golden fixture validates, every invalid fixture is rejected at its expected path, and the axis-box GLB renders at 0.400 × 0.900 × 0.200 m. Representative input: `fixtures/contracts/take-manifest.original.json`. Edge cases: overlapping transform drivers, non-unit quaternion, stale save, duplicate/out-of-order frames. **Out of scope:** any external service (TigerData, Supabase, fal, Chert, Gemini), editor UI, capture adapters. **Cut/fallback:** none needed; external smoke tests move to the lanes.

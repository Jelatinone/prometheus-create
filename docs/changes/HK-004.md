## 1. Outcome and acceptance

**Objective:** the persistent editor shell from PLAN §1 (top menu, left tools, viewport, right inspector, bottom take bar) rendering a `TakeManifest` with Three.js / React Three Fiber: select, move, rotate, uniform scale with undo, numeric inspector, fork a take, switch back to the unchanged original, save through `ProjectRepository`. **Visible flow:** given the fixture original manifest loaded into `MemoryBackend`, when the user selects the axis box, moves and scales it, undoes once, forks, edits the fork, saves, and switches takes, then the original still matches `fixtures/contracts/take-manifest.original.json`, the fork reloads with its edit, and the inspector reads 0.400 × 0.900 × 0.200 m for the unscaled box. Edge cases: a stale save surfaces `REVISION_CONFLICT` to the user (no silent overwrite); GLB node transforms are applied exactly once; selection, orbiting, and playback never create revisions. **Out of scope:** auth and persistence implementation, reconstruction, timeline/physics (HK-008); PNG/GLB export is HK-005, next in this lane. **Cut/fallback:** one object and a static alternate first (PLAN D-010).

Use `forkManifest` / `forkTake` for fork semantics and `objectDimensions` for displayed sizes so the editor and platform agree byte-for-byte.

## 1. Outcome and acceptance

**Objective:** the persistent editor shell from PLAN §1 (top menu, left tools, viewport, right inspector, bottom take bar) rendering a `TakeManifest` with Three.js / React Three Fiber: select, move, rotate, uniform scale with undo, numeric inspector, fork a take, switch back to the unchanged original, save through `ProjectRepository`. **Visible flow:** given the fixture original manifest loaded into `MemoryBackend`, when the user selects the axis box, moves and scales it, undoes once, forks, edits the fork, saves, and switches takes, then the original still matches `fixtures/contracts/take-manifest.original.json`, the fork reloads with its edit, and the inspector reads 0.400 × 0.900 × 0.200 m for the unscaled box. Edge cases: a stale save surfaces `REVISION_CONFLICT` to the user (no silent overwrite); GLB node transforms are applied exactly once; selection, orbiting, and playback never create revisions. **Out of scope:** auth and persistence implementation, reconstruction, timeline/physics (HK-008); PNG/GLB export is HK-005, next in this lane. **Cut/fallback:** one object and a static alternate first (PLAN D-010).

Use `forkManifest` / `forkTake` for fork semantics and `objectDimensions` for displayed sizes so the editor and platform agree byte-for-byte.

## 3. Actual changes and evidence

**Delivered behavior:** a signed-in user opens a saved cloud project at `/projects/<id>` (linked from the project list) in one persistent editor. The editor has:
- **Top bar:** take switcher, saved/unsaved state, Undo/Redo, Save, Fork take, Import GLB, Capture, Export PNG and GLB.
- **Left tools:** Select, Move, Rotate, Scale (V/W/E/R), Frame (F), Camera, Grid. Lasso is shown disabled and labelled "later".
- **three.js viewport:** orbit, click to select with an outline, and a gizmo; the scale gizmo is kept uniform.
- **Right inspector:** object list with show/hide; name; position in m; rotation in ° (XYZ); uniform scale; dimensions with an "Estimated" cue; geometry revision and normalization; provenance; Duplicate and Delete. The scope reads "Scene".
- **Bottom take bar:** take, revision, origin and parent. Timeline is labelled "still take".
- **Capture drawer:** capture's `CapturePanel` writes photos and frames into the project through the platform (`HttpBackend` + `PlatformBlobStore`).

Keyboard shortcuts are disabled while typing. Every edit is one undoable manifest change. Selection, orbit and tool changes never change the manifest. Saves send `expectedRevision`. Forks copy the saved revision and are named automatically (Alternate, Alternate 2…).

**Known limitations / not tested:**

- **Editor prototype by the V1 gate's wording.** Meshes come from the fixture or Import GLB. Live reconstruction (`fal-ai/sam-3/3d-objects`) is proven only by HK-002's CLI and is not wired to an editor button. That needs a split runner plus a server route.
- **Not done:** lasso, timeline and keyframes, physics, splats, the source-reference/Before-After panel, scale confirmation (`user_confirmed`), and the PNG camera picker (PNG uses the current view; **Camera** jumps to the take's camera).
- **Not exercised by hand:** the conflict notice UI and Reload button (the API path was checked); the camera inside the editor (the pane blocks camera access); GLB re-import of an exported file into the editor; mobile layout (the editor is desktop-first).
- **Dev environment:** the dev-mode first load takes about 10 s in the pane. With the pane hidden, client scripts were throttled and a reload sat on "Opening the editor…". The API read-back above was used instead.
- **Untested asset cases:** a GLB with a non-+Y convention is taken at its word (glTF says meters, +Y). Dense meshes (562k triangles from fal) were not loaded in the editor.
